# TG Assistant

Помощник для outreach в Telegram через пул аккаунтов с человеческим поведением и антиспам-логикой.

Идея простая: на масштабе один аккаунт быстро упирается в лимиты Telegram, поэтому работа идёт через пул из десятков или сотен прогретых аккаунтов. Каждый со своим прокси, своим лимитом, своей историей контактов. Один контакт прикреплён к одному аккаунту навсегда — чтобы человек никогда не получил сообщение с двух разных номеров и не пожаловался.

Внутри каждого аккаунта — то же самое, что в одиночной версии: скоринг контактов, генерация в твоём стиле через LLM, отправка с имитацией «человека» и кучей предохранителей от бана.

## Как это устроено

- **accounts** — пул, диспетчер, импорт из CSV. Сердце системы: решает, через какой аккаунт сейчас слать.
- **fetcher** — выгребает диалоги и историю сообщений по каждому аккаунту в локальный SQLite.
- **scoring** — считает «температуру» каждого контакта: тёплый / остывающий / холодный / мёртвый.
- **generator** — берёт топ контактов конкретного аккаунта, подмешивает его собственный стиль из истории и через Claude API генерит несколько вариантов первого сообщения.
- **sender** — крутит пул: каждый драфт уходит через свой `account_id`, диспетчер делает round-robin между аккаунтами с учётом лимитов и FloodWait.

- **dashboard** — FastAPI веб-морда со статусами пула + JSON-API для приёма сессий из внешнего warmup-пайплайна.

Подробности по архитектуре пула — [`docs/MULTI_ACCOUNT.md`](docs/MULTI_ACCOUNT.md). Антиспам — [`docs/SAFETY.md`](docs/SAFETY.md). Дашборд и intake API — [`docs/DASHBOARD.md`](docs/DASHBOARD.md). Переход на свою модель — [`docs/OWN_MODEL.md`](docs/OWN_MODEL.md).

## Поставить

Нужен Python 3.10+. На сервере:

```bash
git clone <repo-url> tg-assistant
cd tg-assistant
./install.sh
```

Скрипт развернёт venv, поставит зависимости (включая `python-socks` для прокси), разложит папки `data/`, `logs/`, `sessions/` и сделает `.env` из шаблона. Дальше открываешь `.env`:

- `TG_API_ID` и `TG_API_HASH` — общий Telegram-app для всего пула, берётся на https://my.telegram.org/apps. Один на все аккаунты, это нормально.
- `ANTHROPIC_API_KEY` — для генерации, с https://console.anthropic.com. Потом можно переключить на свою локальную модель через `USE_LOCAL_MODEL=true`.

Деплой через Docker или systemd — в [`deploy/README.md`](deploy/README.md).

## Как пользоваться

```bash
source venv/bin/activate

# 1. Импорт аккаунтов из CSV (формат см. в accounts.example.csv)
python -m src.accounts.bulk_import accounts.csv

# 2. Авторизация. Если у тебя уже есть .session-файлы (например, из warmup-фермы),
#    положи их в sessions/ — этот шаг можно пропустить.
python -m src.accounts.login --all

# 3. Выкачать историю контактов по каждому аккаунту
python -m src.fetcher.fetch_dialogs --all

# 4. Скоринг (глобально, по всем контактам всех аккаунтов)
python -m src.scoring.score_contacts

# 5. Сгенерировать черновики — для каждого аккаунта по топ-10
python -m src.generator.generate_drafts --top 10

# 6. Запустить отправку. В review-режиме каждое сообщение покажет перед отправкой.
python -m src.sender.send_queue --mode review
```

То же через `make`:

```bash
make accounts-import CSV=accounts.csv
make accounts-login
make fetch-all
make score
make generate TOP=10
make send-review
```

Когда поверишь — `make send-auto` запустит сендер в фоне, он сам будет крутить пул круглыми сутками с паузами на ночь.

## Дашборд и API

`make dashboard` или `docker compose up -d` поднимет веб-морду на `http://<server>:8080`. Логин `admin`, пароль — `DASHBOARD_TOKEN` из `.env`. Видно статус каждого аккаунта, очередь, последние отправки.

Параллельно работает JSON-API для интеграции с warmup-пайплайном. Когда внешняя система закончила прогрев очередного аккаунта — она пушит StringSession в `POST /api/accounts/intake`, и аккаунт сразу попадает в пул. Полная спека и примеры — в [`docs/DASHBOARD.md`](docs/DASHBOARD.md).

## Аккаунты и прокси

CSV-формат (см. `accounts.example.csv`):

```csv
name,phone,session_path,proxy,daily_limit,hourly_limit
acc01,+79001234567,sessions/acc01.session,socks5://user:pass@1.2.3.4:1080,80,8
```

Поддерживаемые прокси: `socks5://`, `socks4://`, `http://`, с авторизацией или без. На масштабе — только резидентские статические, по одному на аккаунт. Подробнее в [`docs/MULTI_ACCOUNT.md`](docs/MULTI_ACCOUNT.md#прокси).

`daily_limit` / `hourly_limit` в CSV перебивают глобальные дефолты из `.env`. Хочешь один аккаунт жать пожёстче — поднимаешь только ему.

## Безопасность

Кратко, что защищает аккаунты:

- per-account дневной и часовой лимит, отдельно для каждого
- ramp-up: первые 14 дней лимит растёт постепенно (отдельно у каждого аккаунта от момента его первой отправки)
- ночное окно (по умолчанию 0–8) — пул спит
- паузы между отправками 7–60 минут, рандомом; вечером чуть короче
- имитация typing, чтение входящих перед отправкой
- блок дублирующихся текстов глобально по всему пулу (одинаковый текст с разных номеров — главный триггер кластеризации в антифроде)
- sticky-маппинг контактов: один человек = один аккаунт навсегда
- `FloodWaitError` → аккаунт уходит в cooldown, остальные продолжают работать
- `PeerFloodError` → аккаунт выводится из ротации насовсем

Все ручки в `.env`, статусы аккаунтов — в таблице `accounts`. Полный список — в [`docs/SAFETY.md`](docs/SAFETY.md).
